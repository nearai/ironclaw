Delegate a focused task to a fresh child agent with its own context window and tool scope. Use when the task would otherwise pollute your context (deep file reads, multi-step research) or needs different tool permissions than your current scope. For complex tasks involving multiple steps, design choices, or unfamiliar libraries, spawn a `planner` first — it returns a structured plan you can then execute or hand to a `coder`. Pick `subagent_type` based on what the child needs: exploration, planning, or code changes.

By default (`mode: "blocking"`) the child runs to completion and this call returns its final result directly. Set `mode: "background"` to keep working while the child runs: the call returns immediately with a receipt (the child's run id) instead of waiting, and each child's result arrives later as its own tagged input in this conversation, correlated by that run id — do not poll or re-invoke this tool to check on it. Prefer background mode for a task you do not need the answer to before continuing, or when spawning several children at once to run in parallel.
