## 频道的工作方式

频道是扩展的一种能力面。安装 Slack 或 Telegram 扩展后，智能体便可在该平台收发消息；扩展清单会在声明其工具的同时声明频道能力面。

启动服务后在 Web 界面中连接频道，设置流程会引导您填写所需凭据，并将其加密存储。

```bash
ironclaw serve
```

---

## 频道设置入口在哪里

这是最容易卡住的地方，因此这里写得具体一些。频道设置分为两半，在两个不同的地方完成：

1. **运维一半（每个实例一次）**：在侧边栏打开 **Admin**，进入 **Configuration**。每个需要部署凭据的频道都在这里有一张配置卡片 —— 例如 **Telegram deployment configuration**、**Slack deployment configuration**。填写字段并保存，取值会加密存储。
2. **个人一半（每位用户各自完成）**：打开 **Extensions**，安装对应扩展，并在其卡片上使用 **Connect** / **Configure**。Telegram 打开的是账号配对面板，Slack 运行的是您个人的 OAuth 连接。也可以直接在聊天中让智能体完成这一半。

<Warning>
配对面板以“部署配置已保存”为前提。如果尚未保存，它只会报错：
*"An administrator must configure the Telegram bot first."*
这条信息看起来像权限不足，实际上不是 —— 请先在 **Admin → Configuration** 中完成运维一半，再进行配对。
</Warning>

<Note>
在聊天中让智能体“连接 Slack / 设置 Telegram”只覆盖**个人一半**：安装并激活扩展、弹出连接或配对面板。运维一半 —— **Admin → Configuration** 中的部署凭据 —— 被有意排除在智能体可驱动的工具之外，需要您在 Web 界面中自行完成。
</Note>

<Info>
Telegram 有**两个**容易混淆的步骤：由运维人员为整个实例保存一次部署配置；随后每位用户再将自己的 Telegram 账号与 IronClaw 用户配对。出现“administrator must configure”提示，说明第一步尚未完成。
</Info>

<Note>
频道凭据保存在加密的密钥存储中，而不是 `config.toml` 里。配置文件只记录存放凭据的环境变量名称，绝不包含凭据本身。
</Note>

## 接收消息

两个频道都通过 Webhook 投递事件，因此消息平台需要能通过 HTTPS 访问到您的 IronClaw 实例。

---

## 不使用频道也可以

您并不一定需要频道。Web 界面和终端连接的是同一个智能体：

```bash
ironclaw repl
ironclaw run -m "我今天的日程是什么？"
```

<Info>
Discord、Signal、微信和企业微信是 IronClaw v1 的功能，不包含在 1.0 版本中。如果您依赖其中某个频道，请继续使用 v1。
</Info>

</Note>
