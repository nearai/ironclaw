Connect IronClaw to a Telegram bot so your agent can receive and reply to messages in
direct messages and group chats.

## Prerequisites

- A Telegram account
- An IronClaw instance reachable from Telegram over HTTPS

---

## Setup

<Steps>

<Step title="Create a bot">

Message [BotFather](https://t.me/botfather) and send `/newbot`. Choose a name and a
username ending in `bot`. BotFather replies with a token that looks like
`123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ`.

<Warning>
The bot token is a full credential for your bot. Anyone holding it can read and send
messages as your agent. Don't paste it into a shared channel or commit it to a repository.
</Warning>

</Step>

<Step title="Start IronClaw">

```bash
ironclaw serve
```

</Step>

<Step title="Enter the bot token (operator, once per instance)">

In the [web interface](/using/webui), open **Extensions**, switch to the **Channels** tab,
and scroll to the **bottom of the Built-in section**. Use **Configure** on the Telegram
card and paste the bot token.

<Warning>
Do not use **Configure** on Telegram from the **Registry** tab. That button opens the
pairing panel, which assumes the bot is already configured, so it can only fail with
*"An administrator must configure the Telegram bot first."* The message sounds like a
permissions problem; it isn't. Use the Channels tab.
</Warning>

The token is stored in the encrypted secret store, and the webhook is registered with
Telegram for you. Telegram delivers updates to:

```
https://your-host/webhooks/extensions/telegram/updates
```

</Step>

<Step title="Pair your account (each person)">

Configuring the bot does not connect *you* to it. Pairing is a separate step that tells
IronClaw which Telegram user corresponds to which IronClaw user. Start a chat with your
bot and follow the pairing prompt.

Pairing is what stops a stranger who finds your bot from talking to your agent as you.

</Step>

<Step title="Talk to it">

Send your bot a direct message. To use it in a group, add the bot to the group — by
default Telegram bots only see messages that mention them.

</Step>

</Steps>

---

## Configuration

Telegram has no settings in `config.toml` and no CLI enablement key. The
ingress route is compiled in and mounted unconditionally; it starts serving
once you install the Telegram extension and finish bot setup in the WebUI
(see the steps above). Until then it returns `503`.

The bot token lives in the encrypted secret store, not in `config.toml`. See
[Configuration](/capabilities/configuration).

<Note>
  A `[telegram]` section left over from an older release still parses, but
  nothing reads it — `ironclaw serve` logs a deprecation notice on boot.
  Delete the section to silence it.
</Note>

## Troubleshooting

<AccordionGroup>

<Accordion title="The bot never replies">
Telegram delivers updates by webhook, so your instance must be reachable over HTTPS with a
valid certificate. Telegram will not deliver to a self-signed endpoint or a private
address.
</Accordion>

<Accordion title="It works in DMs but not in a group">
Either mention the bot directly, or turn off privacy mode through BotFather
(`/setprivacy`) so it can see all group messages.
</Accordion>

<Accordion title="Someone else messaged my bot">
Anyone who knows the bot's username can start a chat with it. Unpaired users are not
treated as you — complete pairing so your agent only acts on your behalf for your own
account.
</Accordion>

<Accordion title='"An administrator must configure the Telegram bot first"'>
The instance-wide bot token has not been set, or you reached the pairing panel from the
Registry tab before it was. Open **Extensions → Channels**, scroll to the bottom of the
Built-in section, and use **Configure** on the Telegram card there.
</Accordion>

<Accordion title="I asked the agent to connect Telegram and it said it couldn't">
Connecting a channel is an operator action and is deliberately not something the agent can
do for you. Follow the steps above in the web interface.
</Accordion>

</AccordionGroup>
