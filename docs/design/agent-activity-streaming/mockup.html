What this argues. Both panes run the identical task. Left is faithful to your recording — raw Activity — N tools disclosures over JSON, a static Working pill, one column. Right keeps every honest detail one disclosure away, but leads with plain-language narration, a live verb + elapsed status, a persistent Plan / Context rail, and IronClaw's safety + connector + handoff surfaces woven into the stream.

Bind-today — already in the webui_v2 stream: the Thinking narration (Thinking item), the grouped tool run with expandable params (CapabilityActivity + activity-run.tsx), the safety-approval gate (Gate event + approval-card.tsx — a surface Cowork has no equivalent for), and the connector / auth card (AuthRequired, with oauth / manual-token / pairing kinds).

Needs a new payload (the real backend gaps): per-tool durations — the UI already renders {ms} but CapabilityActivityView hardcodes null; the live Plan tracker — no plan/todo event exists yet (PlanCard is a client-side mock); the elapsed timer — only point timestamps are emitted; and the background-job chip + multi-channel handoff — jobs are REST-polled (Running→Completed), not on the turn SSE. The status verb is already derivable from ProgressUpdateView.kind + WorkSummary phase.
