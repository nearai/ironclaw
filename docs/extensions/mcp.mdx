The [Model Context Protocol](https://modelcontextprotocol.io/) is an open standard for tool
servers, with a growing ecosystem covering databases, APIs, and cloud services. IronClaw
adapts MCP tools into agent capabilities.

MCP is one of the runtimes an extension can declare, alongside WASM and first-party. An MCP
server reaches your agent by being packaged as an extension whose manifest declares its
tools and endpoint — there is no separate MCP server registry.

---

## Adding a Server

Install and activate the extension that wraps the MCP server:

```bash
ironclaw extension search notion
ironclaw extension install notion
ironclaw extension activate notion
```

Then complete any credential setup from **Extensions** in the
[web interface](/using/webui). Once activated, the server's tools appear alongside every
other tool the agent can call.

Remove it the same way you remove any extension:

```bash
ironclaw extension remove notion
```

## Enrolling a local server

From the trusted **Extensions → Add MCP server** UI, enroll exactly
`http://127.0.0.1:<port>/mcp` and choose bearer authentication. Only the explicit
human enrollment path permits this endpoint; a model tool cannot enroll it.
You can also use the trusted operator CLI:

```bash
ironclaw extension enroll-mcp local-tools --name "Local tools" --endpoint http://127.0.0.1:43127/mcp --json
ironclaw extension install mcp-local-tools --json
```

Complete bearer setup in the native UI. An installer can instead deliver one
credential through an inherited owner-only pipe with
`ironclaw extension import-mcp-token mcp-local-tools --token-fd <fd>`.
The command prints public account metadata only. To rotate in place, supply
`--expected-account <account-id>` from the previous receipt. If a setup process
lost its receipt, `ironclaw extension import-mcp-token mcp-local-tools --inspect-account`
returns the selected public account ID without reading a token or contacting the
endpoint. Mint a replacement credential and import it with that expected ID;
inspection never recovers the old secret.

Use the same native home and configured identity as the running agent. The
inherited descriptor must be a FIFO owned by the current user with mode `0600`.
On macOS, create a named FIFO inside a private directory, open separate read and
write descriptors, then unlink its name before delivering the credential. Close
the writer after delivery. Anonymous process pipes and Node.js stdio sockets do
not meet this descriptor contract. Do not put a bearer in command arguments,
environment variables, or a regular file.

The exception permits only that exact literal host, port, and path, without URL
aliases or redirects. General private-network access stays denied. Persist the
server port and refuse silent takeover: another same-user process that binds
the enrolled port while the server is down could receive its bearer. Use
expiring, scoped credentials that can be revoked at the local server.

## Transport

IronClaw connects to MCP servers over **HTTP(S)** using JSON-RPC 2.0.

<Warning>
The `stdio` transport is not supported. IronClaw rejects it rather than spawning a local
server process, because process-level egress controls have not landed yet. A server that
only speaks stdio cannot be connected today.
</Warning>

## Security

MCP servers are untrusted. A server does not gain ambient filesystem, secret, or network
authority just because the agent can call its tools:

- Calls go through the host-selected client, which is the only integration point
- Outbound requests are planned and authorized by the host's egress controls, not by the
  server
- Resource use is accounted through the host governor like any other capability
- Credentials are injected at the egress boundary and redacted from results and errors

See [Security](/security) and [Sandboxed Tools](/capabilities/sandboxed-tools).

## WASM or MCP?

| | WASM extension | MCP extension |
| --- | --- | --- |
| Runs | Sandboxed inside IronClaw | On a remote server over HTTP |
| Best for | Deterministic logic, offline work, tight sandboxing | Existing MCP servers and hosted SaaS tools |
| Network | Allowlisted egress from the sandbox | The server's own endpoint |
| Latency | In-process | A network round trip |

Prefer a WASM extension when you're writing the tool yourself and want it sandboxed. Use
MCP when the tool already exists as an MCP server.

See [Building an Extension](/extensions/building-a-tool).
