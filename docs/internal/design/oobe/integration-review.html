04

Dependencies & implementation approach

Every dependency states what it needs and how to build it. The frontend data seam is already shaped for all of these — wiring is a mock→fetch body swap with no component change.

Foundational

D-F1Task backend

Needs: the durable source of truth. Approach: 5 redacted events → (tenant,user)-scoped projection (+ isolation test) → 5 routes + descriptor rows → 5 mediated facade methods returning server-confirmed records.

D-F2Suggestion producer⚠ load-bearing

Needs: something must emit the first proposals — not covered by the existing contract. Approach: ship a deterministic starter set gated on admin-whitelisted tools; design the triggers-hosted suggester as the Vision upgrade.

D-F3Connect wiring

Needs: authorize the user's account per tool. Approach: route the card into the existing extension-auth flow via the shared extension_name resolver — no new auth path, no frontend-only fallback.

D-F4Agent mode + gate

Needs: durable mode + real gate behavior. Approach: settings endpoint + session hydration; auto = typed per-kind generalization of global_auto_approve, with gate-suppression tests + audit trail.

D-F5Carousel data safety

Resolved: the always-available surface reads the durable projection and renders no fabricated cards when the feed is empty.

D-F6DESIGN.md + tokens

Needs: IronClaw has no design constitution yet. Approach: seed DESIGN.md with the v2 tokens + card taxonomy; the OOBE cards are the natural pilot. Cross-cutting, deferrable.

Vision (additional)

D-V1Queued OAuth

Superset of D-F3. Batched multi-tool orchestration over the same pairing infra. Frontend-heavy; no new backend auth path.

D-V2Reveal animation

Superset of the static first card. ai-spark sweep on AutomationTaskAutomated (already emitted by D-F1); honored under prefers-reduced-motion.

D-V3Anticipatory states

Superset of the empty landing. “No automations yet” / “working on the first one” projection states through the stream path (#6993).

D-V4Docked drawer

Superset of the pills-collapse drawer. New docked-container component + composer layout; reuses the Foundational state machine.

D-V5Username derivation

Superset of the nameless greeting. Resolve a deterministic source with documented precedence + fallback. Open decision.

06

Decisions reviewers should weigh

These gate the phases they belong to and are cheap to hold, expensive to skip. Full context in PROPOSAL §10.

Phase boundary.

Is the Foundational cut correct, or should a Vision piece (docked drawer, reveal) graduate into Foundational?

The suggestion producer (D-F2).

Deterministic starter set vs. triggers-hosted suggester vs. agent-driven — the one genuinely new mechanism and biggest open question.

Agent-mode gate semantics (D-F4).

Confirm auto as the typed generalization of global_auto_approve, and the bounds of “approved task types” (per-tool / per-action / caps).

Carousel data safety (D-F5).

Resolved: real durable suggestions only; the mock path is removed.

DESIGN.md pilot (D-F6).

Adopt the APDD design track here (DESIGN.md + tokens now, Storybook later), or defer?
