The APDD Kit turns "an AI agent editing files" into "an agent operating inside guard-rails" — four governance layers, two standing rules, and a design-governance track, all copy-in and stack-agnostic. This page reviews what it does and how it fits IronClaw.

Source apdd-kit @ 61daaa2 Scope UI / front-end software Form guides · templates · rules · skills · enforcement Evaluated for IronClaw
Verdict — adopt selectively

IronClaw has already independently built the kit's backend & enforcement half — path-scoped agent rules, CI-enforced regression tests, a rich skills library. The kit's net-new value is its Design/UX governance track (absent today) and a living docs-first feature workflow — and both land on a React/Vite/Tailwind frontend that fits them with unusually low friction. Skip the kit's backend MVVM rules; IronClaw's crate-architecture rules already own that ground.

01 · The framework

Four governance layers, held together by two rules

The kit's core idea: any single artifact may reach the agent as the only governance in context, so each is self-sufficient — and a deterministic enforcement layer binds even when the prose is ignored. Below is the control plane the layers form.

Rule 1 — the spine

Docs are the source of truth

Read a feature's spec + plan before editing its code. Add uncovered behavior → update the spec in the same change. Spec and code disagree → stop and reconcile.

Rule 2 — the spine

Critical fixes update docs + add a test

Same diff: log it in the spec's Critical Bug Fix Log, revise the plan, and add a regression test that fails-before / passes-after. Incomplete without all three.

FIG.1b  ·  Review gate & role routing — inside layer ①, a change's blast radius is declared, a hard team-review gate resolves, and (proposed for IronClaw) the change is routed to the reviewer role that owns the ground it touches.
Declare — spec §5 / plan §4

Impact & dependency, up front

Architecture Impact (which boundaries a change crosses) and Dependencies & Sequencing are written into the spec/plan before code — blast radius is explicit, not discovered mid-review.

Gate — spec §8 (hard)

Team review resolves first

The implementation plan may not begin until the spec's Feedback & Decisions gate is resolved. Kit-native; IronClaw strengthens the generic gate with the role routing below.

▸ Cross-functional trigger — a boundary-crossing diff names the owning reviewer role (checks come from review-discipline.md + the trust-boundary checklist, which name what to inspect, not who); role → person mapping stays in CODEOWNERS.

02 · Why it exists

What the kit buys you

Two priorities drive every artifact: minimize regression and raise product design & development quality when the author is an AI coding agent.

discoverable

Guidance finds the agent

Path-scoped rules inject themselves the moment a matching file is edited — the agent doesn't have to know they exist.

deterministic

The machine is the backstop

Hooks + CI bind regardless of which tool wrote the code or whether it read the prose. Non-compliance is assumed.

portable

Tool-agnostic by design

Ships in Claude Code conventions, but maps cleanly to Cursor, Antigravity, and root-file-only tools.

grounded

Agents stop guessing UI

A Storybook MCP lets the agent read real component props instead of hallucinating them — the single biggest UI-quality win.

living

Docs that don't rot

Specs are the working reference, not creation stubs — every critical fix drags the docs forward with the code.

additive

Adopt only what applies

A UI-focused core plus opt-in modules; nothing in core depends on a module. Copy in, fill placeholders, done.

A design constitution, wired into the build

04 · Opt-in modules

Capabilities only some products have

Include a module only if it applies. For IronClaw, one is directly on-point — it ships LLM agents inside the product.

realtime-media

Live audio/video — encode, codec, simulcast, frame callbacks.

rich-view

Canvas / 3D / embedded-webview GPU surface with its own render loop.

multitenant-isolation

One deployment, many customers; real-time broadcast / fan-out.

embedded-ai-agents

Ships LLM agents inside the product — keys encrypted at rest, per-agent DB config, tenant-scoped context on every call.
